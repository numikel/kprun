# Changelog v0.7.7

All notable changes to kprun are documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [0.7.7] - 2026-11-23

### Changed

- Dependency updates: clap 4.6.7 → 4.6.9 (pulls syn 3.0.10, proc-macro2 1.0.107, quote 1.0.47), rand 0.10.3 → 0.10.4, rpassword 7.5.4 → 7.5.5, zeroize 1.9.1 → 1.9.2; GitHub Actions taiki-e/install-action 2.90.6 and Swatinem/rust-cache (master `eedcf2f`). Supersedes the open dependabot PRs #122, #123, #124, #125, #126 and #127.
- zeroize 1.9.2 wipes secret buffers (master passwords, generated key material) with an optimized bulk fill plus an assembly optimization barrier instead of a byte-by-byte volatile loop; the guarantee that the wipe cannot be optimized away is unchanged.
- On Windows the lockfile now resolves windows-sys 0.52 for errno, rustix, rustls-platform-verifier, tempfile and winapi-util (all declare `>=0.52, <0.62`); no behaviour change.

### Fixed

- Pressing Ctrl+C at the master-password prompt (e.g. `kprun run` without a stored password) no longer leaves the terminal without echo and line editing; fixed by rpassword 7.5.5.

### Tests

- New pty-based `unlock_prompt` integration test drives the real interactive master-password prompt: the typed password unlocks the vault and is never echoed, and Ctrl+C aborts with no child process, no audit record and the terminal restored.
- New unit tests pin: unbiased bits in `init --quick` generated passwords, generated keyfiles are distinct and unlock only their own vault, master passwords are wiped in place by zeroize and redacted in `Debug` output, and `kprun run` argument splitting at `--` together with `Cli::command().debug_assert()`.
